## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host code → SDK store seam | Host-supplied JID strings and typed record payloads cross into SDK parsing and storage |
| Account A ↔ Account B | Isolation boundary enforced structurally (per-account instances) — cross-account bleed is the core security risk of the seam |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-05 | Information Disclosure | Cross-account bleed via cache/chat-index shared state in reference impl | high | mitigate | Per-account sub-dictionaries and per-account ordered index owned by the account-scoped view, keyed (Capability, AccountId); two-account isolation contract facts assert zero cross-reads; scratch impl's different structure doubles as an implementation-coupling check |
| T-01-06 | Tampering | Malformed JID strings accepted and persisted as canonical-looking keys | high | mitigate | Jid.Parse strict grammar with SdkFormatException on malformed input; TryParse-false contract; round-trip canonicalization tests; acceptance criteria pin the grammar |
| T-01-07 | Tampering | Policy leakage into store interface (host-implementers forced to own retention decisions) | medium | mitigate | Primitives-only trim API (Pitfall 5): no TTL/count parameters in interface signatures; compile-time acceptance criterion in Task 1; runtime trim-behavior contract facts in Task 3 |
| T-01-08 | Information Disclosure | Identity/prekey record contents echoed in exception messages | medium | mitigate | Same message discipline as T-01-01: exceptions name operations and rules, never embed record payloads; enforced by plan 01-04's error-surfacing acceptance criteria |
