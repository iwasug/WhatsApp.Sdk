## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host-registered factories → SDK registry | Host factory code executes inside SDK resolution — exceptions and instance lifecycle cross the boundary |
| SDK → ILogger output | D-21 logging could leak account data or record payloads into host log pipelines |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-12 | Information Disclosure | ILogger entries embedding store record payloads or key material | high | mitigate | StoreErrorSurface logs operation name + account ID only — never record contents; retry-policy messages name the operation, not payloads; acceptance criteria assert the logged message contains the operation name and the payload-discipline test in DurableWriteRetryPolicyTests |
| T-01-13 | Denial of Service | One failing store's disposal aborting the cascade, leaking other stores' resources | medium | mitigate | DisposeAsync aggregates: every store gets a dispose attempt; aggregate exception surfaces; unit-proven in Task 3 |
| T-01-14 | Repudiation | Unbounded silent retries masking backend outages (host sees success-shaped latency, never an error) | medium | mitigate | D-18 bounded: 3 attempts then SdkStoreException with inner preserved — exhaustion is thrown, logged via StoreErrorSurface; FakeTimeProvider-proven |
| T-01-15 | Tampering | Host factory returning instances the SDK forgets → unmanaged lifecycle and cross-account reuse of stateful connections | medium | mitigate | D-23: SDK disposes everything it obtained via host factories; D-24 caching prevents duplicate instances per account; unit-proven |
</threat_model>
